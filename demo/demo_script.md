# 4分30秒面试讲解：企业制度问答 Agent

打开[Workspace](index.html)。默认是空白咨询工作区：左侧是本页会话，中间是咨询内容，底部有持续可用的输入框。公开展示采用Guided Replay，没有连接实时模型；固定样例及答案都来自已保存的真实实验。

## 0:00–0:30 从产品使用开始

“这是面向制造业员工的制度问答产品。员工想知道现在适用哪版、自己的部门适用什么范围，以及回答凭什么成立。用户先提出问题，再核对依据。”

选“差旅标准”样例，原问题连同日期、部门会载入输入框；此时尚未出现Agent答复。点击“发送”，打开该问题的真实历史原答。不要把发送动作说成实时调用模型。

## 0:30–1:10 完成一次答案—依据核对

点击北京住宿结论里的 `[1]` 或这条结论本身：该句聚焦，右侧Inspector展开差旅制度及C03对应文本。再点适用范围和版本两句，分别核对C01、C07。关闭Inspector可继续咨询。

“原始Citation是文档级。这里的C03定位是基于已有评分锚点制作的阅读映射，不冒充模型当次输出了条款级引用；实际引用片段与同源全文分开展示。”

## 1:10–2:00 答案正确，不等于引用正确

打开顶部[Cases](cases.html)，选“来源噪声”，查看宽版Baseline / V1.1对照。点击Baseline访客来源，展开原访客片段与原评分“不支持本题”；再查看V1.1差旅来源。

“两边核心答案都正确，但Baseline混入访客制度。我的迭代重点是证据能不能支持当前答案，而不是把这个案例说成准确率提升。”

正常查询与来源噪声共用DIRECT_ANSWER-01，是同一条真实实验的两个阅读视角。

## 2:00–2:50 制度要求，不等于现实状态

Cases选“越界推断”，查看UNSUPPORTED_INFERENCE-05，并用“回答边界”聚焦V1.1“当前制度无法确认”的部分。

“Baseline从验收规则进一步推成现实中缺材料、暂不能付款；题目没有提供这些实际记录。V1.1保留制度条件，也保留实际质量、验收材料和财务状态的未知部分。必要条件不等于已经发生或尚未发生的业务事实。”

想从产品角度体验其他边界，可回Workspace点“换个样例问题”，载入部门澄清或年假问题，发送后查看原答。修改录制日期、任意改写问题等输入不会匹配已有答案，界面会提示选择固定样例，不能让旧回答冒充新问题的结果。

## 2:50–3:30 一次真实失败与恢复

Cases选“技术失败”，查看另一条真实V1.1治理失败记录：安全降级原答、failed原事件、空来源。技术失败不是正确拒答。

再选“失败与恢复”：首次V1在多轮JSON异常后中断，61题结果作为失败实验封存；V1.1增加严格Schema、有界解析、fail-safe与异常隔离。17/17离线故障注入通过，新实验80题序列结束，78题有效、2题治理失败、0服务级中断。

“完整生产退出堆栈没有取得，异常传播机制由离线复现支持；17次测试不是生产稳定性证明。”

## 3:30–4:00 Evaluation

打开[Evaluation](evaluation.html)：引用准确率59.06%到99.22%，V1.1另1条待复核；正确拒答6/11到11/11，B另4例待复核；噪声来源63/80到有效返回中确认0/78，另1例待复核。六项指标及真实分母均保留。

## 4:00–4:30 取舍与项目边界

指出Answer Correctness退化、2例过度拒答与2题治理失败。

“治理更严格也可能让原本可完成的任务受阻，所以不能写整体准确率提升、零幻觉或全部80题成功。实验是14份模拟制度、单次固定回归、单评审初标，不能代表生产可靠性。”

[About](about.html)集中保留产品工作、数据边界、PRD、Bad Case、Processing Logic和截图入口，不让这些材料抢占默认咨询界面。
