# 4分30秒面试讲解：企业制度问答 Agent

打开[在线 Recorded Interactive Demo](https://3219896344y-jpg.github.io/trusted-enterprise-policy-assistant/demo/index.html)，或解压后直接打开[index.html](index.html)。无需登录、API Key或开发环境。按钮只展示已存在的历史实验，不实时调用模型、不生成新答案。

## 0:00–0:30 产品问题

指向首页的产品价值和三项成果。

“我做的是面向制造业员工的制度问答 Agent。员工不只想知道答案，还需要知道现在适用哪版、自己属于什么范围、依据是什么。原版核心答案已经较好，但引用准确率只有59.06%，也出现了无依据业务推断。我优先做证据治理和回答边界，而不是继续堆功能。”

## 0:30–1:10 正常查询

点击“01 正常查询”，再点击已录制问题，显示V1.1真实回答。打开差旅引用，核对2026制度、北京每人每晚550元、普通员工适用范围；继续展开制度原文。

“用户先获得明确答案，再自己核对依据。这里的引用片段是当轮真实展示的来源；展开的全文来自同一文件，不冒充模型当轮引用了整份制度。”

本场景与下一场景共用DIRECT_ANSWER-01，分别讲产品使用和证据对照，不是额外两次实验。

## 1:10–2:00 答对，也可能引用错

点击“02 来源噪声”，切换“Baseline”与“V1.1”，再选“并排对照”。展开Baseline访客制度引用，指出它与住宿标准无关；再展开V1.1差旅来源。

“两边核心答案都正确，但Baseline来源混入访客制度。用户看到多个来源，会难以判断哪一条真的支持金额。V1.1关注的是答案和证据的一致性。这不能讲成该题答案准确率提高。”

## 2:00–2:50 制度要求，不等于业务现实

点击“03 越界推断”，查看UNSUPPORTED_INFERENCE-05并排原回答和来源。

“Baseline把制度的验收要求进一步推成现实中缺材料、暂不能付款。但用户没有提供实际验收和付款记录，制度也不能证明它们是否存在。V1.1说明可以确认的制度条件，同时保留实际质量、材料和财务状态的未知部分。我的产品判断是：必要条件不等于已经发生或尚未发生的事实。”

不要改读成理想答案。页面保留模型完整原文，讲解只解释已经记录的差异。

## 2:50–3:30 失败与恢复

点击“04 失败与恢复”，按顺序查看“发生了什么 → 根因证据 → 修复 → 验证”。

“首次V1回归在多轮治理JSON异常后中断，61题结果作为失败实验封存。V1.1增加严格Schema、有界解析、fail-safe和异常隔离。17/17离线故障注入通过；新实验从头跑完80题序列，78题有效、2题治理失败，0服务级中断。”

补充一句：“完整生产退出堆栈未取得，异常传播是离线复现支持的机制；17次测试不是生产稳定性证明。”不展示不存在的原中断完整对话。

## 3:30–4:00 Evaluation

点击“05 Evaluation”，在同一页查看结果；需要深入时再打开[完整展示页](evaluation.html)或[冻结报告](https://github.com/3219896344y-jpg/trusted-enterprise-policy-assistant/blob/main/docs/evaluation_report.md)。

“引用准确率59.06%到99.22%，V另1条待复核；正确拒答6/11到11/11，B另4例待复核；噪声来源63/80到有效返回中确认0/78，另1例待复核。失败题没有可评分来源，不算治理成功。”

## 4:00–4:30 局限与产品取舍

指出取舍区的Answer Correctness退化、2例过度拒答和2题治理失败。

“治理更严格也会让任务更难完成。FOLLOW_UP-08对原本可回答的报销时限发生过度拒答。因此我不会写整体准确率提升或零幻觉。数据是14份模拟制度、单次固定回归、单评审初标，不能代表真实企业生产可靠性。这个版本已经停止开发，保留改善、退化和争议，作为完整的产品迭代案例。”
