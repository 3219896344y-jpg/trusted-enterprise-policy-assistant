## 结论边界

- 同一冻结 1.0.1、同顺序/输入；每 case 新会话，多轮使用模型真实前答。未传 gold。正式不因内容差重试。
- tool_trace_complete=false。治理日志覆盖本模块的输入、选择和输出，不构成完整 Agent 内部检索审计。不能把端到端变化归因于单独的检索算法。
- 80 题是固定回归集；开发前已经分析 B 错误，且中断 V1 已产生61题输出，绝非严格未见盲测。原 V1-XQ-1.0.1-SINGLE-01 单独封存，不纳入本次最终成绩。Dev 使用另建场景；没有针对正式 case ID 写规则。
- 模型别名不保证供应商权重快照恒定；不同时间窗口与随机性未消除。没有显著性检验，没有生产可靠性结论。
- B→V1.1比较包含原V1的证据/回答治理和本轮可靠性修复，不能把全部质量变化归因于JSON Schema校验或异常隔离。
- 标注者能识别治理输出风格，未做组别盲化，也未双人独立评分。争议见review_required.md。观察区间不是统计置信区间。
- 运行期间曾有一次只读SQLite采集失败，随后只重读成功；未修数据库、未重发模型请求。该采集工具事件与模型运行错误分开记录于collection_notes.json。
- 治理层使用同一模型；程序只检查引用存在、日期/部门等结构条件，不证明全部语义正确。保留错误、退化与争议，不把无错误观察写成“零幻觉”。
