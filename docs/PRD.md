# 制度查询助手 · 产品定义与最终范围

状态：V1.1 已结束迭代，2026-10-01。本文记录实际交付范围，不把未实现的设计写成能力。

## 用户与任务

普通员工需要确认制度是否适用于自己、当前标准及下一步需要哪些材料。HR、财务和行政维护人员需要可核对的来源、明确的未知边界和可追踪 Bad Case。

首版覆盖差旅、报销、请假、培训、采购审批、外协/访客入场。数据为“星桥制造有限公司”14份**模拟制度 / 演示数据**，含10份有效制度与4份失效制度。

## 问题与优先级

Baseline 核心答案已较高，但引用准确率仅59.06%，确认11/80出现无依据业务推断。因此 P0 是来源相关性与回答边界；版本和部门适用性作为证据约束保留。没有为追求全面性新增权限后台、制度编辑器、真实审批流或业务系统接入。

## 用户路径和行为

提问 → 原版检索/读文档 → 候选证据治理 → 回答与来源。用户可在原版 Sources 面板查看原文。

| 情形 | 产品行为 | 验收关注 |
|---|---|---|
| 证据充分 | ANSWER | 核心事实正确，来源支持结论 |
| 部分有依据 | PARTIAL_ANSWER | 已知规则与无法确认的业务事实分开 |
| 缺少影响结论的部门/主体/日期 | CLARIFY | 不偷偷假定，避免无必要追问 |
| 当前资料无依据 | NO_EVIDENCE | 不补造公司规定 |
| 治理处理失败 | 技术失败与安全降级 | 不冒充拒答，不暴露未经治理的草稿 |

不将“未规定”变成“禁止”，不将“需要批准”变成“一定不能报销”，不将“预算通过”变成“已验收或已付款”。旧版保留在知识库，仅用于有日期的历史说明。

## 验收与取舍

独立28题 Dev Set；固定80题回归，8类问题，6项指标。同步观察过度拒答、部分回答质量、B正确→V错误与治理失败。最终接受2题治理失败与准确率退化，不继续优化。详见 [评测报告](evaluation_report.md)。

## 已知边界

无真实企业接入、身份权限管理、版本发布后台、逐句可点击证据链或生产SLA。语义支持判断仍依赖模型；程序校验不是事实正确性的证明。目标是可运行、可展示、可复核的 AI 产品实践。
