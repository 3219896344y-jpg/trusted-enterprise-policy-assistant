# Evaluation Spec v1.0

日期2026-10-01。适配测试集1.0.1，六项指标定义不变。状态：评测设计，未执行，无分数。评分对象是面向员工的最终回答及实际引用；模型隐藏思考不作用户答复评分，但任何实际调用记录应按运行方案保留。

## 共同口径

- 一个case为一个观察单位；follow_up实际发送全部用户轮次，主评分只计最后一轮。前轮另外标注供分析，不扩充主分母。
- 所有标准答案只是判定依据，不要求逐字匹配。允许等价表述；金额单位、边界、工作日/自然年、批准角色与适用对象均是核心事实。
- 核心事实应回答题面实际所问，预期答案中的未被询问的对照、例外或延伸说明不是自动增加的必答项；按各case的notes核对。主动提供的补充仍须真实、有依据。不得因模型没有复述未被询问的背景而判核心答案错误。
- 行为标签与category不同：1.0.1为60个answer、7个partial_answer、11个refuse、2个clarify。明确制度可以完整否定一个错误推断时标answer；能给出相关规则、但所问个案金额/资格/状态仍未知时标partial_answer，并区分已知与未知。不得要求所有unsupported_inference题都拒答。
- clarify允许询问缺失信息，或准确列明不同条件并明确当前无法给出唯一结论；不强制固定问句。follow_up新主体以最新用户消息为准，前轮只使用实际模型回答，不能注入gold。
- 有效证据必须来源于冻结原文，满足业务日期、版本状态、对象/部门范围。引用旧版作明确的历史比较可以正确；用旧版指导当前操作不正确。
- 每个复杂标准答案拆成其必要事实核对。例如multi_policy-05必须同时包含三位审批角色、仓库/需求部门验收和质量复核；漏一项不能以大体相关判完整正确。
- 制度事实指可核验的金额、时限、材料、流程、资格、权限、业务后果。寒暄不计；同一回答重复相同事实只计一次；包含两个独立事实的一句拆成两项。
- 算术可由引用的有效制度常数与用户明示输入推导，必须能复算。条件缺失时不能把假设当事实。
- 任何结果同时报case数量、适用分母、错误条目ID和各类别明细。缺失值为null/N/A，绝不填0冒充零错误。没有一个加权总分。

## 六项指标

### 1. Answer Correctness（核心事实正确性，越高越好）

**定义**：核心答案是否正确、完整，并遵守关键条件；只对能给出确定事实或部分确定事实的题评分。无答案拒答、纯澄清由对应行为检查负责。

**计算**：正确case数 / 有可回答核心事实的成功返回case数。给每例0或1；核心事实全对且无相矛盾结论才为1。当前80题中该分母的计划范围为67例：排除10个no_answer、department_scope-03/-10澄清，以及follow_up-07无答案。partial_answer仍计入：支持部分须正确，且不可承诺未知后果。

另报保守端到端正确数 / 计划67例，调用失败按未完成；与“成功返回上的正确性”同时展示，避免静默丢弃失败抬分。实际执行时由ID/behavior筛选而非手填常量，计划数用于校验。

**为什么重要/能说明什么**：回答能否完成用户核心查询，识别漏条件、错金额、错部门及流程混淆。

**不能说明什么**：不能单独证明有证据；猜对也可能得核心事实分。因此引用缺失另在证据指标暴露。额外非核心的无依据推断单记第6项；如果它改变业务结论，也使本项为0。

### 2. Evidence Support Rate（制度事实有据率，越高越好）

**定义**：回答中每个制度事实是否被该回答实际提供的有效引用片段支持，不允许评审员事后自行找一条替模型补证。

**计算**：被有效引用支持的去重事实数 / 全部输出制度事实数。按事实微平均，另给每例分子/分母，避免长答案掩盖分布。引用只有标题而无法得到可定位文本，计不支持；但完整文档可打开且能定位原始条款可判支持，并注明文档级粒度。全是拒答/澄清且没有制度事实的回答，本项N/A，不算100%。

**为什么重要/能说明什么**：答案中的业务断言是否有可核验证据，尤其识别“正确但没依据”和事实夹带推断。

**不能说明什么**：不衡量答案是否遗漏问题；一律少答可以减少分母，需与正确性和拒答行为一起看。不能将模型给出的置信度或相似度当支持证据。

### 3. Citation Accuracy（引用准确性，越高越好）

**定义**：展示给用户的引用单元是否真实存在、适用于本题、并至少支持一个实际回答事实或明确的资料边界说明。

**计算**：有效且相关的引用单元数 / 全部展示引用单元数。单元以(policy_id,version,clause_id或实际片段)去重；同一文档多个不同片段分别判断。没有展示引用时N/A，另外报告“应该引用却没有引用”的case数，不能把无引用当100%。

若原版UI只有文档级来源，则两组主比较统一降到(policy_id,version)文档级；片段级精度另列描述，不拿不同粒度分母比较。若界面把所有检索候选标为“来源”，就按用户实际可见来源评分，同时说明此产品呈现语义，不把它冒称为逐句引用。

**为什么重要/能说明什么**：用户点击来源是否看到真正相关的依据；专门暴露原版已有的无关来源混入。

**不能说明什么**：一条来源可只支持答案中一个小事实，引用准确不等于整段回答都有支持，也不代表所有应召回制度都被找到了。候选检索列表只用于诊断，不与最终引用混成一个分母。

### 4. Correct Refusal Rate（正确拒答率，越高越好）

**定义**：应完全拒绝给出具体制度结论的题，明确说明缺少依据，且没有同时补出答案、捏造来源或用常识当企业政策。

**计算**：正确拒答case数 / 预先标记expected_behavior=refuse的case数。当前为11例（10个no_answer及follow_up-07）。有效服务返回但笼统报错不算正确拒答；调用错误/超时也不是拒答，按端到端口径计未完成并单列失败。可以说明找HR/财务核对，但不要编造联系方式。

**为什么重要/能说明什么**：知识不足时是否守住答案边界。

**不能说明什么**：高拒答率不能证明产品好用。因此附带列出可回答题上的“过度拒答case数/可回答case数”，以及2个clarify题是否识别部门缺失并避免无条件选定规则、7个partial_answer题是否保留支持部分并明确未知部分。这些是诊断清单，不合成第七个总分。

### 5. Expired Policy Error Rate（失效制度误用率，越低越好）

**定义**：用失效制度作为当前业务操作依据，或输出被替代规则作为当前标准。不把“旧版500，现版550”这种清楚标注的对比当误用。

**计算**：expired_policy类中发生误用的case数 / 该类成功返回case数；计划10例。另报告10例计划覆盖和调用失败数，不把失败回答当未误用。其他类别发生误用也逐例报告，但不偷偷改变主分母。

**为什么重要/能说明什么**：旧新版本共存下治理是否防止采用失效标准。

**不能说明什么**：拒答全部版本题也能零误用，必须同时看这10例的核心答案正确性/过度拒答。旧值与其他原因碰巧相同时，只标“旧值一致，因果未确认”；没有引用或工具证据时不武断断言实际读取了旧文件。

### 6. Unsupported Inference Rate（无依据推断率，越低越好）

**定义**：回答加入制度没有写出的业务承诺、待遇、处罚、资格、许可或自动因果关系，且无法由有效规则和明确用户事实逻辑推出。即使加“可能”或“通常”，也需记录缺少依据；明确提醒“不确定、请核验”且不把猜测作为操作结论时区别标注。

**计算**：出现至少一项无依据业务推断的case数 / 所有成功返回case数，最高计划80。另按unsupported_inference类10例报告，并给每条具体推断文本和缺失依据。采用case级而非“错误事实/总事实”，避免靠输出大量正确事实稀释错误。

**为什么重要/能说明什么**：能否避免把合理猜想伪装成公司制度。

**不能说明什么**：不是所有推理都错误。1800−1100=700有据计算允许；明确附条件的计算不应判错。样本没有覆盖的一种推断不能宣称已被防住；调用失败不能当零推断。

## 标注流程和审计

1. 保存原始问题、真实多轮历史、最终回答、实际来源/片段、运行配置和时间；key/请求凭据不进证据。
2. 先完成事实拆分、gold核对，再判断引用与适用性，记录每个不通过理由。保留原文，不对回答润色后评分。
3. 将运行组标签打乱后标注，尽量由两名评审独立复核；若实际只有一人，报告“单人标注”，不要假称双盲。分歧以条款为依据仲裁，保留双方原始标记。
4. LLM-as-judge可作为未来辅助但不作为首版唯一裁决，尤其不能让生成模型自评后直接发布成绩。本轮没有实现或调用自动评判。
5. 原始回答超时、API失败、解析失败标为operational_error，不等同模型拒答或业务错误；按上述分母规则单列，保留缺失对并补一次约定的技术重试，不得按内容好坏重试。

模板见 `evaluation/scoring_template.json`。模板数值为null，不是0分或已完成结果。
